# 模板实现范围与检查边界

`AGENTS.md` 保留完整维护规范。本文件区分已实现的模板工具和必须在具体研究项目中补齐的部分。

## 已实现的检查接口

`make check` 不联网、不自动初始化依赖、不写入跟踪文件：
检查工作区与索引的一致性、`.gitmodules` 与 gitlink 一一对应、默认挂载路径和 URL 规则、
复现 JSON 区块与索引的完整 SHA 一致、普通 blob 的 10 MB 上限、常见模型/原始数据路径限制、
论文输入目录中的符号链接、2 MB 以上图件的说明入口。

`make check-history` 增加历史 blob 检查，含提交后又删除的大文件。
普通 `check` 只检查索引，不扫描整个历史。CI 使用 history 模式。

已初始化的直接子模块会检查 HEAD 与索引 pin 一致和工作区状态；
递归 submodule status 会检查嵌套 pin 偏离、冲突与未初始化状态。
`make check-dependencies` 在已有依赖未初始化时退出非零。
`make submodules` 只在安全前提满足时执行显式 checkout 模式的递归恢复。

`record-pins` 明确写入复现记录，但不自动暂存、提交或推送。
`manifest` 是环境/状态快照，不等于复现验收；若有未提交变化，会记录 dirty。
`release-manifest` 要求干净 checkout，但仍不替代科学与权限审阅。

## 不应被误认为已自动保证的事项

真实数据/结果正确性、理论推导、引用可靠性、实验误差与容差、图件是否对应所述实验，
均需项目测试及人工审阅。文件扩展名筛查不是完整的数据识别或秘密扫描器。
图件说明出现路径只是结构检查，不证明理由充分。

自动递归 checkout 证明该次环境能够取回 pin，不证明任意未来时点可取回，
也不证明它已进入团队批准的上游分支。发布前独立验证批准分支/保留标签与存档。
代码/实验仓库没有反向依赖论文这一点需要检查真实构建配置并执行独立运行。

Tylina 排除设置、私有仓库凭据、GitHub 模板开关、分支保护、许可证选择，
都不由本地 ZIP 自动设置。缺少所需能力时必须报告 BLOCKED / NOT RUN。

## 工作流与权限

`paper-ci.yml`：push(main / paper-* 标签)、pull_request、手动触发；
不拉取真实依赖，运行索引/历史检查、模板回归测试、固定版 Typst 编译及清单生成。
Actions 固定完整提交，权限为 contents: read，不持久化 checkout 凭据。

`dependencies.yml`：main 推送或 main 手动触发；在全新 runner 递归拉取固定依赖；
按声明执行代码仓库轻量测试；无依赖时输出 NOT RUN，不制造实验通过结果。
默认面向公开依赖，未配置私有访问时会失败，不假装已处理。

`figures.yml`：仅 main 手动触发；需要真实依赖和绘图实现，上传生成图件而不提交回仓库。
模板实验仓库故意不生成假数据图，因此其默认 figures 命令退出 2。

提交前缀与 PR 内容提供规范及模板，**未安装 commitlint 或设置强制 PR 标题检查**。
受保护分支和必需检查需在实际 GitHub 仓库中配置；本模板不声称已启用。
